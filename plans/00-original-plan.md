# Implementation Plan: Self-Modifying Mac App
## Stack: Tauri 2.0 (Rust) + SQLite + LLM API

This document outlines the architecture, step-by-step phases, and core code blueprints required to build a native macOS application that can rewrite its own code and database schema dynamically through a chat interface.

---

## 🛠️ System Architecture

The application operates in a **dual-mode loop**: the frontend handles the conversational interface, the Rust backend handles low-level system permissions (writing files, running commands), SQLite stores app state/memory, and the LLM acts as the runtime compiler.

```
+-------------------------------------------------------------+
|                      User Chat Interface                    |
+-------------------------------------------------------------+
                              │ (1) User Prompts Changes
                              ▼
+-------------------------------------------------------------+
|                      Tauri 2.0 Backend                      |
+-------------------------------------------------------------+
                              │ (2) Packs Prompt + Current Source
                              ▼
+-------------------------------------------------------------+
|                          LLM API                            |
+-------------------------------------------------------------+
                              │ (3) Returns JSON (New Code + SQL)
                              ▼
+-------------------------------------------------------------+
|                      Rust & SQLite Engine                   |
+-------------------------------------------------------------+
                              │ (4) Overwrites Local Code Files
                              │ (5) Executes Database Migrations
                              ▼
+-------------------------------------------------------------+
|                 Vite Dev / Dynamic Webview                  |
+-------------------------------------------------------------+
                                (6) UI Instantly Hot-Reloads
```

## 📋 Step-by-Step Execution Plan

### Phase 1: Environment Setup
*   **Step 1.1:** Install the necessary prerequisites via terminal (`xcode-select --install` and Rust via `rustup`).
*   **Step 1.2:** Initialize a new Tauri 2.0 project using your preferred frontend framework (React + TypeScript recommended).
*   **Step 1.3:** Configure the official Tauri 2.0 SQL plugin to automatically provision a local SQLite file in the application's secure data folder.

### Phase 2: Building the Chat & Context Engine
*   **Step 2.1:** Create a conversational chat panel UI in the frontend (`src/components/ChatPanel.tsx`).
*   **Step 2.2:** Implement a system state extractor in Rust that scans the current frontend source directory (`src/`) and reads file contents into an array of strings.
*   **Step 2.3:** Set up the API client connecting to your choice of LLM (e.g., Anthropic Claude or OpenAI GPT). Make sure to pass a strict System Prompt forcing JSON output.

### Phase 3: The Self-Modification Loop (Hot-Swapping)
*   **Step 3.1:** Write the Rust `update_app_source` command to securely overwrite disk files without crashing the process.
*   **Step 3.2:** Write the Rust `execute_dynamic_migration` command to apply raw SQL strings generated by the LLM directly onto the SQLite instance.
*   **Step 3.3:** Enable local hot-reloading. During development, Vite will automatically catch the disk change and refresh the viewport instantly.

### Phase 4: Production Compiling Strategy
*   **Step 4.1:** **The Production Problem:** Compiled Tauri binaries embed frontend assets. To make it modify itself post-distribution, change the Tauri asset configurations to resolve files from a writable user directory (like `~/Library/Application Support/your-app-name/dist/`).
*   **Step 4.2:** Build a script to copy default assets to this directory on the first boot, and load the webview window directly from that path.

## 💻 Core Code Blueprints

### 1. Tauri 2.0 Backend Setup with SQL Plugin (`src-tauri/src/lib.rs`)
```rust
use std::fs;
use std::path::PathBuf;

// Command allowing the AI to write new code directly to disk
#[tauri::command]
fn update_app_source(file_path: String, new_content: String) -> Result<String, String> {
    let target_path = PathBuf::from(&file_path);
    
    // Prevent directory traversal attacks
    if !target_path.starts_with("src/") {
        return Err("Access Denied: Can only edit files inside the src/ folder.".into());
    }

    match fs::write(&target_path, new_content) {
        Ok(_) => Ok(format!("Successfully updated {}", file_path)),
        Err(e) => Err(format!("Failed to write to file: {}", e)),
    }
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_sql::Builder::default().build()) // SQLite plugin
        .invoke_handler(tauri::generate_handler![update_app_source])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

### 2. Frontend Bridge to LLM & Rust (`src/components/ChatPanel.tsx`)
```typescript
import { useState } from 'react';
import { invoke } from '@tauri-apps/api/core';

interface LLMResponse {
  filePath: string;
  newCode: string;
  sqlMigration?: string;
}

export function ChatPanel() {
  const [prompt, setPrompt] = useState("");

  const handleSendPrompt = async () => {
    // 1. Fetch current file content to give LLM context (Simplified example)
    const currentCode = "export function App() { return <div>Original UI</div> }"; 
    
    // 2. Call your LLM API route with context + user prompt
    const response = await fetch("https://api.openai.com/v1/chat/completions", {
        method: "POST",
        headers: { "Authorization": `Bearer YOUR_KEY`, "Content-Type": "application/json" },
        body: JSON.stringify({
            model: "gpt-4o",
            response_format: { type: "json_object" },
            messages: [
                { role: "system", content: "You edit apps. Return JSON matching: { filePath: string, newCode: string, sqlMigration?: string }" },
                { role: "user", content: `Edit this file: ${currentCode}. User request: ${prompt}` }
            ]
        })
    });
    
    const data = await response.json();
    const aiResult: LLMResponse = JSON.parse(data.choices[0].message.content);

    // 3. Invoke the Tauri Rust command to hot-swap the code file
    await invoke('update_app_source', { 
        filePath: aiResult.filePath, 
        newContent: aiResult.newCode 
    });

    // 4. (Optional) Run SQL migrations if returned
    if (aiResult.sqlMigration) {
        // execute migration using tauri-plugin-sql
    }
  };

  return (
    <div className="chat-container">
      <input value={prompt} onChange={(e) => setPrompt(e.target.value)} placeholder="How should the app change?" />
      <button onClick={handleSendPrompt}>Evolve App</button>
    </div>
  );
}
```

## ⚠️ Crucial Safety & Constraints Checklist

*   **Guardrails:** Always validate that the LLM is modifying files purely inside the frontend layout path (`src/`). Never let it modify `lib.rs`, `Cargo.toml`, or access system binaries to prevent unauthorized command execution or loops.
*   **Backups:** Before executing `fs::write`, copy the target file to a `src/.backup/` cache folder so the user can easily hit an "Undo" button if the LLM generates a breaking compilation error.
*   **App Sandbox:** Keep Apple's Sandbox settings disabled during local development, or configure specific entitlements to allow reading and writing file locations outside the binary bundle.
